# 화요전도단·목요사명자교육 개발 계약

## 요청된 기능

- 두 교육을 묶는 교육 관리 탭. HTML과 Next.js 양쪽에 같은 기능/동선을 제공한다.
- 주간 조직별 요약과 총계, 부서 클릭 상세, 교육별 총 재적 대비 참석률.
- 참석·지각·불참·공무 구분.
- 부서장이 자기 소속 사명자의 공무 사전보고: 소속, 대상자, 개인별 사유, 추후 교육 방법, 교육 결과.

## 먼저 재사용할 기반

| 기존 기능 | 파일 |
|---|---|
| 교육 재적, 부서/지역 집계, 오전·저녁 중복 제거 | `server/lib/edu-attendance.js` |
| 재적·참석률·공무 표, 엑셀/이미지 보고 | `next-app/components/attendance/EduAttendanceReport.tsx` |
| 화전단/목사교 날짜별 24부서 공무 선택·미리보기·감사·충돌 검사 | `next-app/components/report-admin/ExcusedAdmin.tsx`, `server/actions/edu-excused.js` |
| 공무 원자적 전체 명단 교체와 이력 | `supabase/migrations/20261113091030_edu_excused_reviewed.sql` |
| 과정·정기교육·모임별 업무 위임 | `server/lib/education-access.js` |
| 일반 과정 관리 | `next-app/components/education/Education.tsx`, 루트 `app.html`의 관련 관리 화면 |

기존 사유는 **명단 전체 변경 이유**다. 개인별 공무 사유와 교육 방법/결과는 추가 요구다. 현재 공무 관리의 전체 교육 위임 조건을 자기 부서장 권한이 구현된 것으로 보지 않는다.

## 필수 저장 설계

`getEduExcused` / `previewEduExcused` / `applyEduExcused`, DB의 `edu_excused_state` / `edu_excused_apply`를 먼저 읽는다. 기존 처리는 교육 종류·날짜의 `#excused` 명단을 전체 교체한다. **부서 화면의 부분 목록을 이 API에 보내면 다른 부서 기록이 삭제될 수 있다.**

새 부서장 처리는 서버가 확인한 담당 범위의 추가·수정·취소만 반영하도록 계약을 제안한다. 클라이언트의 소속 드롭다운을 권한 근거로 삼지 않는다. 다른 부서 기록 보존, 동시 변경/버전 충돌, 전체 관리자 화면·봇과의 병행을 검증한다. 단순히 이 화면을 열기 위해 모든 교육 출석 편집 권한을 부여하지 않는다.

출석·재적은 기존 원본을 재사용한다. 개인별 공무 상세와 보완교육 정보만 필요한 만큼 추가하며, 공무 원본과 별도 상세가 서로 어긋나지 않도록 단일 저장 계약을 정한다. 이름은 표시용이고 대상자/회차는 안정적인 ID로 연결한다. 기존 표/열 삭제·이름 변경·구형 쓰기와 호환되지 않는 필수값 도입은 피한다. 운영 SQL 실행은 이번 개발 범위 밖이다.

## 보존할 계산

- 교육별 대상 재적을 사용한다. 전체 교사 명단을 분모로 임의 대체하지 않는다.
- 현재 24부서 보고에서 실제 참석이 공무보다 우선한다.
- 공무는 일반 불참에서 제외하지만 참석률 분모에는 포함한다.
- 지각은 참석의 일부다. 네 배타적 칸을 만들 경우 정시 참석과 전체 참석을 구분하여 중복 합산하지 않는다.
- 오전·저녁 참석과 겸직/조직 분류의 중복을 주의한다.
- 보완교육 완료는 당일 실제 참석과 별개로 기록한다. 과거 출석과 이미 보낸 보고를 자동 수정하지 않는다.
- 새 저장으로 기존 Telegram 보고를 중복 발송하지 않는다. 실제 발송 없이 모의 요청으로 검증한다.

## 담당자에게 확인할 기준

1. `교자장어부청`의 ‘어’ 의미와 표시 순서.
2. 교회/신학, 교자장부청, 24부서가 서로 배타적인 소속인지 별도 분류인지.
3. 두 교육의 대상 재적과 주간 회차 기준.
4. 부서장 직책·겸직 범위, 보고 즉시 공무 확정 여부와 별도 확인 필요 여부.
5. 사전보고 마감, 사후 수정/취소, 결과를 입력/확정할 담당자.
6. 참석률 분모 변경 요구가 있는지. 결정 전에는 기존 계산을 유지한다.

미확정 규칙을 임의로 운영 정책으로 만들지 않는다. 화면/가짜 응답 작업은 진행할 수 있다.

## 완료 판정

- 같은 데이터로 A/B 화면·통계·내보내기 결과가 일치한다.
- 자기 범위 처리는 성공하고 타 부서/권한 회수는 거절된다.
- 두 부서 동시 저장과 기존 전체 관리 화면의 병행에서도 기록이 사라지지 않는다.
- 사유·교육 방법·결과·취소의 실행자/이력이 남는다.
- 전체 A 복귀 후 새 기록이 보존되고 기존 기능이 작동한다.
- 공유 기능 중지와 A 복귀를 별도로 확인한다.
- 로컬/모의/실제 브라우저/실기기/외부 연동 결과를 구분한다.
