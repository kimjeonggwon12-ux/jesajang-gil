# 교사광장 공동 배포 절차와 작업 현황

Claude와 Codex는 공통 저장소의 개별 브랜치에서 개발한다. 작업마다 한 사람이 수정과 검증을 책임진다. 운영 배포는 사용자와 범위를 정한 담당자가 한 번에 하나씩 진행한다. 다음 담당자는 직전 배포의 검증까지 확인하고 이어받는다.

## 작업 현황

| 업무 | 담당 | 다음 확인 |
| --- | --- | --- |
| 목요 사명자 교육 집계 기준과 예약 실패 기록 | Codex | 운영 주소의 최신 배포와 후보 소스를 대조해 반영하고 결과를 기록한다. |
| 목요 보고방 수신과 수동 게시 여부 | Claude | 기존 최종 보고와 누락된 오전 보고의 실제 수신 여부를 확인한다. 수신 확인 결과를 공유한 뒤 사용자와 보완 발송 범위를 결정한다. |

작업 시작 시 이 문서 또는 해당 PR에 담당자, 기준 소스, 수정 범위, 상태를 남긴다. 같은 파일이나 업무에 영향이 있는 작업은 담당자끼리 먼저 조율한다.

## 배포 순서

1. [공동 개발 기준 브랜치](START_HERE.md)의 최신 상태와 운영 주소에 연결된 실제 배포의 소스를 확인한다. 별도 후보에서 배포한 변경도 다음 후보에 포함한다. A·B 화면과 공통 서버의 영향 범위를 확인한다.
2. 후보 소스, 변경 범위, 현재 배포의 복귀 경로를 기록한다. 정기 교육 보고 수정은 운영 정책·재적·수신 설정의 연결을 읽기 전용으로 점검한다. 같은 설정으로 오전·최종 결과를 발송 없이 생성해 전환 전 기준과 대조한다. 미완료 회차와 자동 재시도 범위도 확인한다.
3. 배포 전에 진행 중인 다른 운영 배포가 있는지 확인한다. 후보 빌드를 검증한 뒤, 운영 주소를 연결하기 직전에 현재 배포를 다시 확인한다. 다른 배포가 먼저 반영됐다면 새 운영 소스를 기준으로 후보를 다시 검증한다.
4. 연결 후 운영 주소, A·B 진입, 변경 기능을 확인한다. 자동 보고는 예약 실행 결과의 성공 여부와 단계별 실패 기록, 업무 담당자가 확인한 실제 수신 결과를 기록한다. 과거 보고 보완은 회차와 단계별 수신 및 발송 이력을 대조하고 기존 재시도 경로를 사용한다.
5. [변경 기록 양식](CHANGE_TEMPLATE.md)에 담당자, 변경 범위, 검증, 복귀 경로와 후속 작업을 남긴다. 공유 문서에는 절차와 상태만 적고 상세 운영 증적과 비밀값은 교회 관리 환경에 보관한다.
