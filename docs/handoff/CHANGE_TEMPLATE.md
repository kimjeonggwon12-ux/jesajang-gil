# 기능 변경 전달 양식

- 작업 브랜치 / 기준 커밋 / 최종 커밋:
- 요구사항과 바뀐 동작:
- A HTML 변경 파일·진입 동선:
- B Next.js 변경 파일·진입 동선:
- 공통 API/권한/계산 변경:
- DB 변경 제안 / 기존 A·B와의 호환 / 추가 기록을 보존하는 복구 방법:
- 기능 기본 꺼짐 및 중지 시 조회·기록 보존:
- 검증 환경(합성 DB 이름·포트 또는 모의 응답):
- 실행한 명령과 통과/실패/미실행:
- 성공 데이터 비교 / 타 부서 거절 / 동시 저장 / A 복귀 결과:
- 모바일 브라우저와 실제 설치 PWA 검증 범위:
- 실제 외부 서비스 호출 여부(기본 없음):
- 담당자 확인이 남은 업무 기준:
- 남은 문제와 전환 측 검토 요청:

실제 이름·고유번호·연락처·비밀값·운영 캡처는 넣지 않는다. PR 대상은 공유 기준 브랜치이며 운영 브랜치로 합치지 않는다.
