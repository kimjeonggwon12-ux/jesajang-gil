# Next.js 개발 지침

루트 `AGENTS.md`와 `../docs/handoff/START_HERE.md`를 먼저 읽는다.

- A의 HTML 화면과 같은 메뉴·입력·결과·동선을 유지한다. 신규 교육 화면도 양쪽에서 같은 기능과 계산을 제공한다.
- `app/api/route.ts`는 기존 `../api/index.js`를, 그 API는 공통 `../server/`를 사용한다. 브라우저에 DB 권한·서비스 키·서버 업무 모듈을 넣지 않는다.
- 개인 정보를 정적 HTML/공용 캐시에 넣지 않는다. 로그아웃·계정 변경·화면 닫힘 뒤 늦은 응답이 이전 정보를 되살리지 않게 한다. 쓰기 요청을 자동 재시도하지 않는다.
- 교육 업무 위임은 서버 응답으로 판단한다. 전체 현황 조회 권한과 개인별 사유·서류·상담 열람 권한을 혼동하지 않는다.
- `public/`은 생성물이다. 정적 허용 목록과 워커는 루트의 `tools/prepare-next-legacy.mjs` 및 `worker/`에서 관리한다. 서버·문서·환경 폴더 전체를 복사하지 않는다.
- `proxy.ts`, 공통 세션, `worker/pilot-bridge.js`, 서비스 워커, A/B 경로는 전환 담당과 조율한다. 전체 A 복귀는 공통 DB/API를 되돌리는 작업이 아니다.
- 기존 `npm run dev/start`는 전환 담당자의 가짜 DB 런타임 파일을 필요로 한다. 공유 시작 문서의 DB 없는 검증부터 실행하고, 로컬 브라우저 검증은 별도의 합성 환경을 준비한다.
- 공통 빌드 확인은 루트의 `npm run build:handoff`를 사용한다. 운영 배포를 수행하지 않는다.
- 핵심 변경/검증만 한국어 문서로 남기고 실제 휴대전화/PWA·외부 발송을 모의 검사와 구분한다.
